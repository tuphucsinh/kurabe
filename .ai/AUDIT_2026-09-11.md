## Findings and adjudication

### F01 — High: evaluation retry can move an already advanced evaluation backwards
- `src/actions/evaluation.ts:248–263`: after a zero-row repeat submit, the action sees old round Submitted and changes the parent status to that old round's next status without testing current_round or monotonic progress; returns success even if the repair UPDATE errors.
- Example: Employee evaluation has progressed to Approved; the originally assigned R1 evaluator replays R1 submit while period remains Active. The branch attempts Approved → Submitted, leaving current_round/final fields unreconciled. UI button disabling is not a server authorization/transition guard.
- `:197–228,278–385`: default path still splits round write, next-round creation, parent update and best-effort rollback into separate requests. Missing/false transactional flag reaches it. P99 history guard protects personnel columns, not a general monotonic parent-status transition.
- Classification: VERIFIED source control flow; actual DB interleaving/affected-row proof pending. Repair must cover save, retry, init, return, races and both flag states. Do not auto-enable a production flag.

### F02 — High: transactional grading can pin a version different from the version used to calculate
- `src/actions/evaluation.ts:115–158` calculates from gradeSnapshot but passes only criteriaConfigVersionId to the RPC builder.
- `src/lib/evaluation-transaction-rpc.ts:5–22,77–94` has no grade version parameter.
- `supabase/migrations/20260907000500_grade_config_version.sql:345–355` fills missing grade_config_version_id with whichever version is currently active. A config change between scoring and write can label old calculated results with the new version.
- Criteria overload at `supabase/migrations/20260907000600_criteria_config_version.sql:571–629` does not close grade-version propagation.
- Classification: VERIFIED interface omission and source-backed race; disposable DB concurrency test required. Historical P99M3T01 advisory was not fully closed by criteria-only propagation.

### F03 — High: reset-pending login and session issuance race are distinct from accepted optional legacy login
- Reset RPC `supabase/migrations/20260905072000_p98_password_setup_transaction.sql:133–148` sets hash=NULL, setup_required=true and revokes sessions.
- `src/actions/auth.ts:77–99` ignores setup_required in OPTIONAL mode. Actual action with mocked DB accepted the post-reset state and inserted a session without a password.
- `src/actions/auth.ts:49–54,85–109` uses a user snapshot before password compare, then inserts a session without a credential revision condition. Actual action interleaving probe inserted a session after the mocked credential was replaced.
- Preserve intentionally accepted never-configured legacy NULL login. Proposed reset-pending distinction is local security candidate work, not global strict enforcement. Owner must approve exact live credential semantics/cutover.
- Also `src/actions/auth.ts:146–160` ignores DB revocation errors and always reports logout success; local cookie removal is not proof that a copied server token was revoked. Cover this in the same session lifecycle task.

### F04 — Medium: password length validation ignores bcrypt's byte boundary
- `src/lib/auth-password-setup.ts:31–53` accepts up to 72 JS characters; bcrypt consumes at most 72 UTF-8 bytes.
- Actual helper + installed bcrypt probe: 25 characters / 73 bytes accepted; changing the final suffix still authenticates. Synthetic inputs only.
- Fix byte-aware validation in server/UI without silently truncating or bulk resetting existing passwords; retain explicit compatibility policy and tests around 71/72/73 bytes, Vietnamese and emoji.

### F05 — High: login admission is not atomically reserved; proxy trust is not proven
- `src/actions/auth.ts:39–40,85–98` checks before bcrypt and records after failure. Concurrent requests can all pass the count check before any failure is recorded. Atomic record insertion alone does not bound admitted password comparisons.
- `src/lib/login-rate-limit.ts:308–346,458–488` falls back on broad RPC errors/exceptions; failed recording results are ignored by login action.
- `:191–249` accepts forwarded values without a verified immediate-peer boundary; cf-connecting-ip is considered trusted when present. Actual production header overwrite/peer topology is UNKNOWN; do not assert a deployed exploit.
- Add admission reservation and explicit supported proxy contract. Verify real concurrent DB + action tests, generic failure behavior and bounded expiry. No live trust config change here.

### F06 — High: personnel authorization is outside the transaction and can fail open on lookup error
- `src/actions/users.ts:65–77` inspects existingUser but discards lookup error. A failed first read followed by successful existence read at `:85–91` can forward an unauthorized existing target into applyPersonnelTransaction.
- `:94–95` passes no actor scope. Personnel RPC locks/validates graph relations, not the Leader's authoritative permission against a changed target at transaction time.
- `:161–170` soft-delete bypasses the personnel transaction used by upsert/team deletion; leadership/dependent evaluator reconciliation must be explicitly tested rather than inferred from upsert tests.
- Classification: VERIFIED source seams; no live unauthorized mutation attempted. Require injected read error and concurrent target-move/demotion tests, no partial graph changes, protected historical snapshots.

### F07 — Medium: AI summary loses coverage truth after persistence; score selection ignores submission state
- `src/actions/ai-summary.ts:59–80` selects any positive-score round rather than latest submitted result. Draft scores can enter an official-looking summary; valid zero-score submissions are excluded.
- `:101–108` persists summary/creator/time only; `:15–27` reads no coverage metadata; `src/components/reports/AiSummaryCard.tsx:23,38–41,67` keeps coverage warning only in transient generation state. Reload loses partial warning; `src/actions/ai.ts:417–453` can reuse it as complete-looking input to minutes.
- Per-comment truncation at `ai-summary.ts:71` occurs before row coverage calculation. Employee codes are pseudonyms, not anonymization; current label overstates privacy.
- Add persisted coverage/input-version metadata, explicit legacy UNKNOWN, authoritative submitted-result selection and byte/row truncation disclosure. Verify reload, empty/zero/negative fixtures within supported score domain, regeneration and close race.

### F08 — Medium: AI transport allowlist validates only the initial URL
- `src/lib/ai.ts:99–107,150–158,214–258` validates raw base URL then uses fetch without redirect policy. A redirect response can move payload delivery outside initial host policy.
- Classification: VERIFIED missing redirect guard, downstream exposure conditional on provider redirect and fetch behavior; no external exploit or paid call attempted.
- Fail closed on redirects or validate every hop with a tight bounded policy; synthetic loopback redirect fixture only. Extend the same rule to chat's transport seam after caller inventory.
